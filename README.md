Self-hosted vision models on [Ollama](https://ollama.com) as an OCR engine for
[Paperless-ngx](https://github.com/paperless-ngx/paperless-ngx) — shipped as a
plugin, with no changes to the core and no custom Docker image required.

This is a fork of [paperless-mistral-ocr](https://github.com/jensfr1/paperless-mistral-ocr)
by Jens Franke (GPL-3.0-or-later). The plugin structure, the PDF text-layer
renderer and the Tesseract fallback are his; the OCR call is replaced by a
per-page request to a local Ollama instance, so no document leaves the server
and there is nothing to pay per page.

## Why

Paperless-ngx 3.1 ships a remote OCR parser, but it only supports Azure AI
Document Intelligence. Since 3.1 there is also an official plugin interface for
parsers via the `paperless_ngx.parsers` entrypoint group. This package uses it
instead of forking the core: no self-built image, no merge conflicts on updates.

The difference to Mistral OCR is one call: Mistral takes a whole PDF and returns
markdown plus bounding boxes. Ollama takes one image, so the plugin rasterises
each page, sends it, and assembles the archive from the per-page replies.

## What it does

1. Each page is rasterised at 200 dpi (`PAPERLESS_OLLAMA_OCR_DPI`)
2. The page image is sent to `/api/chat` with a transcribe-only prompt
3. The reply becomes the document text
4. An invisible text layer is laid over the page image with ocrmypdf's fpdf2
   renderer, and `pikepdf` merges the pages into the archive PDF

Note that ocrmypdf is used **purely as a renderer** here — no OCR engine is
involved, Tesseract is not called at all in this path.

Born-digital PDFs for which Paperless requests no archive are never sent to the
model, which saves both GPU time and a redundant second text layer.

Because there is one request per page, a 20-page PDF is 20 requests. Nothing is
lost when a single page fails: the other pages are kept and only a total failure
triggers the Tesseract fallback.

## Requirements

- Paperless-ngx **3.1** or newer (needs the parser plugin interface)
- An Ollama instance the container can reach, with a vision model pulled
- No extra Python packages: httpx, pikepdf, ocrmypdf, Pillow and pdf2image all
  ship with the official paperless-ngx image
- No API key: a local Ollama needs none

## Installation

### Without a custom image (recommended)

The official image runs every script in `/custom-cont-init.d/` on start, so the
plugin reinstalls itself on every container start — including after updates.
`docker compose pull` keeps working as usual.

```bash
# 1. Copy the plugin onto the server
scp -r paperless-ollama-ocr your-server:/opt/paperless-ngx/plugins/

# 2. Install the init hook (must be owned by root, not world-writable)
ssh your-server '
  mkdir -p /opt/paperless-ngx/custom-init
  cp /opt/paperless-ngx/plugins/paperless-ollama-ocr/deploy/custom-init/*.sh \
     /opt/paperless-ngx/custom-init/
  chown -R root:root /opt/paperless-ngx/custom-init
  chmod 755 /opt/paperless-ngx/custom-init
  chmod 744 /opt/paperless-ngx/custom-init/*.sh
'
```

Then add the mounts to the `webserver` service in `docker-compose.yml`:

```yaml
    volumes:
      - /opt/paperless-ngx/custom-init:/custom-cont-init.d:ro
      - /opt/paperless-ngx/plugins:/opt/plugins:ro
```

Set the endpoint and model in `docker-compose.env` and restart:

```bash
PAPERLESS_OLLAMA_OCR_ENDPOINT=http://192.168.1.50:11434
PAPERLESS_OLLAMA_OCR_MODEL=deepseek-ocr
```

The log must show:

```
[ollama-ocr] Installation successful.
[ollama-ocr] OK - parser loads.
[ollama-ocr] endpoint http://192.168.1.50:11434 reachable, 3 model(s).
Loaded third-party parser 'Ollama OCR Parser' v0.1.6
```

> **Line endings matter.** The shell scripts need Unix line endings (LF). If
> they are edited on Windows and transferred with CRLF, the init hook aborts
> with `$'\r': command not found` — Paperless then starts normally but
> **without** the plugin and silently falls back to Tesseract. `.gitattributes`
> pins LF for `*.sh`; transfer with
> `cat script.sh | ssh host "tr -d '\r' > /target/path"` if in doubt.

### Reaching Ollama from inside the container

This is the step that trips people up. `localhost` inside the container is the
container, not the host:

| Where Ollama runs | `PAPERLESS_OLLAMA_OCR_ENDPOINT` |
|---|---|
| Another machine on the LAN | `http://192.168.1.50:11434` (needs `OLLAMA_HOST=0.0.0.0`) |
| On the Docker host (Linux) | `http://host.docker.internal:11434` plus the `extra_hosts` line below |
| On the Docker host (Docker Desktop) | `http://host.docker.internal:11434` |
| In its own container | `http://ollama:11434` on a shared compose network |

```yaml
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

By default Ollama only listens on `127.0.0.1`. To accept requests from the
container or the LAN, start it with `OLLAMA_HOST=0.0.0.0:11434` (for systemd:
`systemctl edit ollama` → `Environment="OLLAMA_HOST=0.0.0.0:11434"`).

The init hook and `deploy/check-ollama.sh` both probe the endpoint from inside
the container, so a wrong address is reported at container start rather than on
the first document.

### With a custom image

Only worth it if the container starts without network access. Add to the
Dockerfile of your own image:

```dockerfile
COPY paperless-ollama-ocr /tmp/plugin
RUN pip install --no-deps --no-cache-dir /tmp/plugin && rm -rf /tmp/plugin
```

The downside: you have to rebuild on every Paperless update, `docker compose
pull` no longer gets you new versions.

## Configuration

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `PAPERLESS_OLLAMA_OCR_ENDPOINT` | no | `http://localhost:11434` | Ollama base URL as seen **from the container**. |
| `PAPERLESS_OLLAMA_OCR_MODEL` | no | `deepseek-ocr` | Model name, as in `ollama list`. |
| `PAPERLESS_OLLAMA_OCR_SCORE` | no | `30` | Priority. The built-in remote parser scores 20, Tesseract 10 — higher wins. |
| `PAPERLESS_OLLAMA_OCR_PREPROCESS` | no | `true` | Run ocrmypdf first to deskew and rotate pages, so the archive PDF is upright. Roughly 8 s per document. |
| `PAPERLESS_OLLAMA_OCR_FALLBACK` | no | `true` | Fall back to Tesseract when every page fails, instead of storing empty text. |
| `PAPERLESS_OLLAMA_OCR_FORCE` | no | `false` | Transcribe even when Paperless requests no archive, i.e. PDFs that already carry a text layer. |
| `PAPERLESS_OLLAMA_OCR_DPI` | no | `200` | Rasterisation DPI. 200 is enough; 300 costs twice the runtime for little gain. |
| `PAPERLESS_OLLAMA_OCR_MAX_SIDE` | no | `2400` | Longest side of the image sent to the model; larger pages are downscaled for the request only. `0` disables. |
| `PAPERLESS_OLLAMA_OCR_TIMEOUT` | no | `600` | Seconds per page. |
| `PAPERLESS_OLLAMA_OCR_NUM_CTX` | no | `8192` | Context window per request. |
| `PAPERLESS_OLLAMA_OCR_PARALLEL` | no | `1` | Pages in flight at once. Only useful with `OLLAMA_NUM_PARALLEL` > 1 and the VRAM for it. |
| `PAPERLESS_OLLAMA_OCR_STRUCTURED` | no | `false` | Ask for line-level bounding boxes as JSON. See below. |
| `PAPERLESS_OLLAMA_OCR_BBOX_SPACE` | no | `auto` | `auto`, `pixel`, `normalized1000` or `fraction` — how to read the boxes. |
| `PAPERLESS_OLLAMA_OCR_KEEP_ALIVE` | no | `5m` | How long the model stays loaded between documents. |
| `PAPERLESS_OLLAMA_OCR_PROMPT` | no | – | Replaces the built-in instruction. |
| `PAPERLESS_OLLAMA_OCR_API_KEY` | no | – | Bearer token, only for an Ollama behind an authenticating proxy. |

Registered MIME types: PDF, PNG, JPEG, TIFF, BMP, GIF, WebP.

## Which model

Measured on one machine (Apple silicon, Ollama 0.40.15), one A4 page
rasterised at 200 dpi, model already loaded. The "hard" page is 14 px table
text, skewed 3°, with a low-contrast stamp; it checks six values
(customer number, meter number, consumption, down payment, total, stamp).

| Model | Simple page | Hard page | Values found |
|---|---|---|---|
| `deepseek-ocr` | 8.1 s | 8.2 s | 6/6 / 6/6 |
| `qwen2.5vl:3b` | 6.4 s | 27.6 s | 6/6 / 6/6 |
| `qwen3.8:27b` (MLX, 18 GB) | – | 106.6 s | 6/6, but table rows interleaved |
| `granite3.2-vision:2b` | – | 47.2 s | 1/6, digits wrong, degenerate loop |

`deepseek-ocr` is the default: it is built for transcription, and on the skewed
page it was 3.4× faster than `qwen2.5vl:3b` with the same result — including the
low-contrast stamp and the umlaut in `Zählernummer`. Its cost is a 6.7 GB download
and Markdown formatting in the stored text (`**bold**` amounts, `#` headings).

`qwen2.5vl:3b` is the better pick if you want plain text without Markdown, a 3 GB
download, or Ollama older than 0.13 (which `deepseek-ocr` requires). It kept table
rows on one line where the larger models did not. The 27B model was 13× slower
than `deepseek-ocr` and reordered the table; granite repeated a currency token
until it hit the token limit and misread three of the six values.

Caveats from the same runs: `qwen2.5vl:3b` wrote `Kundennummer` as `Kundenummer`
and `Zählernummer` as `Zahlernummer` once each, so single
characters do occasionally shift. That is the level of error to expect from a
vision model as opposed to a character classifier — it reads better than
Tesseract on layout and worse on exact glyph fidelity.

If you have a model that already works for you, benchmark it rather than trusting
this table: render or photocopy one page whose contents you know, run it through,
and check whether the amounts, names and dates survived. Model quality varies
enough between Ollama builds that a five-minute test beats any published number:

```bash
ollama run deepseek-ocr "Transcribe all text on this page, exactly as printed."
# then point PAPERLESS_OLLAMA_OCR_MODEL at it and consume a real scan
```

## Bounding boxes

`PAPERLESS_OLLAMA_OCR_STRUCTURED=false` (the default) asks for plain text, and
the invisible text layer is laid across the whole page in reading order. Search,
copy-paste and the index all work; only the exact position of each word in the
PDF text layer is approximate.

Turning it on asks the model for one box per line. In the test above,
`qwen2.5vl:3b` on the simple page returned **a single box for the entire
transcription** and took 5× as long, which is why the default is off. Models
that emit real per-block boxes — DeepSeek-OCR's `<|ref|>…<|det|>` layout format
is parsed too, as are the common `bbox`, `bbox_2d`, `box` and polygon shapes —
benefit from it. `PAPERLESS_OLLAMA_OCR_BBOX_SPACE` pins the coordinate system if
auto-detection guesses wrong: `auto` trusts pixels and only falls back to a
0–1000 grid or fractions when the numbers cannot be pixels.

Boxes that do not survive normalisation are dropped rather than clamped, and the
page falls back to the full-page layout. A misplaced text band looks fine in the
index but ruins copy-paste, so a missing position is preferred to a wrong one.

### DeepSeek-OCR

`deepseek-ocr` is the most OCR-focused model tested and the fastest on the harder
page (8.1 s / 8.2 s). It answers with light Markdown
— `#` headings and `**bold**` amounts survive into the stored text, which is
harmless for search but visible in the content field. A leading `<|im_end|>` token
is stripped.

It does **not** emit layout boxes through Ollama in the tested build (0.40.15):
neither the plain transcribe prompt, nor `<|grounding|>Convert the document to
markdown.`, nor `<|grounding|>Given the layout of the image.` produced any
`<|det|>` output, so its pages get the full-page text layer. This parser still
understands the `<|ref|>…<|det|>[[x0,y0,x1,y1]]<|/det|>` format for deployments
where the model does emit it (vLLM, or a future Ollama build) — it is detected
automatically and needs no setting.

Two practical notes: the context window is 8k, which
`PAPERLESS_OLLAMA_OCR_NUM_CTX` matches by default, and a short prompt such as
"Parse the text in the image." returned an empty answer, so keep the explicit
transcribe instruction rather than shortening it.

Some form-shaped pages come back as HTML tables (`<table><th colspan="1">…`)
rather than lines of text. Those are flattened to one `cell | cell` line per row
and any leftover markup is stripped, so neither the search index nor anything
downstream that classifies the document ever sees tag soup. A page that consists
only of markup yields empty text and goes through the normal per-page failure
path.

### deepseek-ocr is fragile on dense form pages

Measured on a certificate-style form page (6.5 pt labels, a 90°-rotated stamp, a
signature scribble), rendered at two resolutions:

| Model | 200 dpi (1654×2339) | 300 dpi (2481×3507) |
|---|---|---|
| `deepseek-ocr` | 4/5 fields, clean text | **empty** at native size; **13 000-character repetition loop** when downscaled to 2400 or 1600 px |
| `qwen2.5vl:3b` | 4/5 fields, clean text | 4/5 fields, clean text at every size |

Both models truncate the rotated stamp to `ANY ALTERATION OR ERASURE` and neither
reads handwriting — that part is not fixable here. But the failure *mode* matters:
`deepseek-ocr` degrades into silence or a loop on this kind of page, which is why
0.1.5 retries an empty answer at 1600 px and 0.1.6 rejects repetition loops
rather than storing them.

Practical consequence: keep `PAPERLESS_OLLAMA_OCR_DPI=200` (higher does not help
any model here), and use `qwen2.5vl:3b` for form-heavy archives — certificates,
licences, anything with boxes, stamps and small print. `deepseek-ocr` remains the
better choice for plain prose pages, where it is also roughly three times faster.

## FAQ

### Do I lose any functionality compared to Tesseract?

Two of the three trade-offs the Mistral plugin documents are the same here; one
is better.

**Page rotation and deskewing: handled.** `PAPERLESS_OCR_DESKEW` and
`PAPERLESS_OCR_ROTATE_PAGES` are options of the ocrmypdf *pipeline*, and that
pipeline does not run here — ocrmypdf only renders. The plugin therefore runs
ocrmypdf as a geometry-only pass before the model call
(`PAPERLESS_OLLAMA_OCR_PREPROCESS`, on by default), with `tesseract_timeout=0`
so only the page images are corrected and the text still comes from the model.

**Archive PDFs get larger**, because every page is re-rasterised at 200 dpi
instead of reusing the original PDF: 95 KB for a one-page image here, ~1.2 MB
for the two-page test PDF. This has no workaround; it follows from how the text
layer is built.

**`PAPERLESS_OCR_LANGUAGE` is ignored.** The model detects the language itself,
which is an advantage for mixed-language archives.

Unaffected: thumbnails, page counting, date detection from text, metadata
extraction, and your existing tags and correspondents. PDF/A is not produced —
but Paperless only produces PDF/A when `output_type` is set accordingly; with the
default `pdf` nothing changes here.

### Why did my PDF not go to the model?

Paperless decides per document whether OCR is needed, and a parser plugin cannot
override that on its own. Two core settings matter:

- `PAPERLESS_OCR_MODE` (default `auto`) skips OCR for PDFs where `pdftotext`
  finds enough embedded text
- `PAPERLESS_ARCHIVE_FILE_GENERATION` (default `auto`) skips the archive PDF for
  born-digital documents that already contain text

When no archive is requested, this plugin reuses the existing text layer instead
of calling the model — inherited from the Mistral plugin, where it saved money —
and logs:

```
Ollama OCR skipped - Paperless requested no archive, so the existing text layer
is used. Set PAPERLESS_OLLAMA_OCR_FORCE=true to transcribe these documents anyway.
```

You can tell it apart from a real run at a glance: a run that used the model
always logs `Ollama OCR: <n> pages in <t>s (model <name>).`, and a skipped one
logs `pdftotext exited 0` under `paperless.parsing.ollama`. A consumption that
finished in a few seconds likewise never touched the GPU.

To run the model on those documents, pick one:

| Goal | Setting |
|---|---|
| Replace the text *and* get a searchable archive PDF | `PAPERLESS_ARCHIVE_FILE_GENERATION=always` (core) |
| Replace the text only, keep the original PDF as archive | `PAPERLESS_OLLAMA_OCR_FORCE=true` (this plugin) |
| Re-OCR scans whose embedded text is bad | `PAPERLESS_OCR_MODE=redo` (core) |

`ARCHIVE_FILE_GENERATION=always` is the cleaner choice: Paperless then asks every
parser for an archive, so the archive PDF and the text layer stay consistent, and
the same rule applies if the document ends up on Tesseract instead.
`FORCE=true` is the narrower one — text only, no archive, useful when you do not
want a second rasterised PDF per document.

Note that `ARCHIVE_FILE_GENERATION=always` increases storage for born-digital
documents: every page is re-rendered as an image at 200 dpi, roughly 95 KB per
page instead of reusing the original.

### What happens if Ollama is unreachable?

Two layers. `score()` probes `/api/tags` once a minute, so while the endpoint is
down the parser declines and Paperless uses Tesseract for that document — you get
the result you would have had without the plugin. If the endpoint dies between
the probe and the request, every page fails, and the Tesseract fallback runs
(`PAPERLESS_OLLAMA_OCR_FALLBACK`). Set it to `false` if you would rather have an
empty document and a loud error than a silently worse one.

This matters because the parser registry picks an engine *before* processing and
does not retry with a different one on failure.

### Does my data leave my server?

No. The only HTTP calls are to the endpoint in `PAPERLESS_OLLAMA_OCR_ENDPOINT`.
Nothing is sent to Mistral, OpenAI or anyone else, and there is no API key.

### How slow is it?

One request per page, so runtime is page count × per-page time. Expect 5–30 s
per page on a reasonably modern GPU or Apple silicon with a 3B-class model, and
minutes per page on CPU. Paperless queues consumption, so this shows up as lag
behind the inbox rather than as an error. Two dials: `PAPERLESS_OLLAMA_OCR_DPI`
(200 → 150 costs little accuracy and a lot of pixels) and
`PAPERLESS_OLLAMA_OCR_PARALLEL` together with `OLLAMA_NUM_PARALLEL`, which only
helps if the GPU has spare VRAM.

### Will it survive Paperless updates?

The install hook runs on every container start, so normally yes. The plugin
subclasses `paperless.parsers.remote.RemoteDocumentParser` though — if upstream
renames or moves that class, the import breaks. That case is handled loudly
rather than silently: the init hook verifies the import and logs a prominent
warning, and `check-ollama.sh` reports it. Paperless keeps running on Tesseract
in the meantime.

### Can I convert existing documents?

Yes, per document:

```bash
docker exec -u paperless -w /usr/src/paperless/src paperless-webserver-1 \
  python3 manage.py document_archiver -f -d <DOCUMENT_ID>
```

This replaces text and archive PDF; the original scan and all metadata stay
untouched. Back up first — `document_exporter` or a database dump. Convert a
handful first and compare: a vision model is better on layout and umlauts, but it
can also quietly drop a single character, and you want to see that on your own
documents rather than on all of them at once.

## Background

The OCR plumbing — the fpdf2 text-layer renderer, the band layout, the
score/fallback lifecycle — comes from Jens Franke's
[paperless-mistral-ocr](https://github.com/jensfr1/paperless-mistral-ocr), which
in turn grew out of [paperless-ngx#13085](https://github.com/paperless-ngx/paperless-ngx/pull/13085).
This fork keeps that code close to upstream so that fixes stay easy to merge,
and replaces the single document-level API call with per-page Ollama requests.
